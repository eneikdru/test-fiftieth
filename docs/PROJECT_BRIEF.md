# Project Brief

## Customer Job

The client's own entries, quoted verbatim and in the client's own language. This file is

1. Разработать веб-систему "База знаний по эпидемиологии" для каталогизации, поиска и управления эпидемиологическими материалами, протоколами и данными.
   
   Заказчик — российский научно-исследовательский институт эпидемиологии.
   
   Важные детали:
   
   1. Язык интерфейса — русский. Все подписи, заголовки, сообщения об ошибках и пустые состояния на русском языке. Английский интерфейс заказчику не подходит.
   
   2. Рынок — Россия. Обработка персональных данных должна соответствовать российскому законодательству.
   
   3. Что загружают: сотрудники института загружают документы — протоколы расследования вспышек, отчёты эпиднадзора, наборы данных, методические руководства. Форматы PDF и офисные документы.
   
   4. Кто ищет: сотрудники института ищут по названию, по автору-организации и по году публикации. Найденный документ должен открываться и скачиваться.
   
   5. Что считается найденным: поиск возвращает документы, которые действительно загружены в систему. Пустой каталог должен честно показывать, что материалов нет, а не примеры.
   
   6. Доступ: просмотр и поиск — для всех сотрудников, загрузка и удаление — только для администратора.

2. Полнотекстовый поиск внутри самих PDF-файлов и документов. Возможность находить документы по вхождению текста внутри файлов (например, поиск по фамилии для приказов, выписок с учёного совета, отчётов и результатов экзаменов).

3. Сводная выгрузка и формирование единой справки по персоналии/фамилии. Возможность отобрать все связанные документы (приказы, выписки из учёного совета, отчёты, экзамены) по конкретному сотруднику/фамилии с формированием списка для просмотра и генерацией итоговой сводной справки по шаблону.

4. Полноценный интерфейс авторизации и регистрации пользователей: сделать понятным процесс регистрации новых сотрудников, добавить явную форму регистрации, сделать ссылку на вход очевидной и доступной в шапке системы, настроить плавный онбординг пользователей.

5. Сводные и аналитические справки по произвольным периодам (конкретный месяц, несколько месяцев на выбор, полный календарный год) и научным направлениям (вирусология, бактериология, эпиднадзор, вакцинопрофилактика). Возможность гранулярной фильтрации состава документов: например, только научные публикации по конкретному сотруднику или все приказы и выписки за выбранный год. Экспорт сводного документа в единый PDF-файл.

6. # ВИШЛИСТ: КОНСОЛИДАЦИЯ ЕДИНОГО ПОРТАЛА (SPA HUB INTEGRATION)
   
   ## 1. Проблема Потока Ценности (Lean Waste: Island Production)
   В репозитории созданы разрозненные функциональные экраны (dossier-harness.html, privacy-harness.html, registration-harness.html, test-harness.html). Пользователь, заходящий на главную страницу (index.html), видит только базовый каталог и не имеет доступа к аналитике досье и GDPR-панели.
   
   ## 2. Требование к Автономной Консолидации:
   Объединить все существующие компоненты в единую навигационную оболочку на главной странице (src/main/resources/static/index.html и frontend/index.html):
   - **Единая шапка (Header) с навигационными вкладками:**
     1. Вкладка 1: «Каталог протоколов» (существующий поиск и список документов)
     2. Вкладка 2: «Аналитика досье» (интеграция компонентов из dossier-harness.html и DossierBuilder.svelte)
     3. Вкладка 3: «Категоризация очагов» (интеграция сервиса RootCauseService)
     4. Вкладка 4: «Безопасность & GDPR» (интеграция компонентов из privacy-harness.html и PrivacySettings.svelte)
   - **Переключение вкладок без перезагрузки страницы (SPA Client Routing).**
   - **Исключение служебных артефактов:** Полное маскирование технических логов и изоляция служебных файлов.
   
   ## 3. Критерии Фальсификации (Acceptance Criteria):
   - H1 (Связность графа): Клик по вкладкам '#tab-dossier' и '#tab-privacy' на главной странице открывает соответствующие функциональные модули.
   - H2 (Достижимость): Расстояние в графе переходов от главной страницы до любого функционала d(v0, fi) <= 1 клик.
